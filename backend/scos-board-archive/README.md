# scos-board-archive

게시판 글·댓글 원본과 revision을 별도 SQLite 파일에 보관하고, 검색 문서의 변경분과 현존 id 집합을 만든다. 본문을 분류·요약하지 않으며 첨부는 URL만 보관한다.

프로젝트 의존은 scos-spi뿐이다. ingest는 소비 앱이 수행한다. SQLite 연결은 보관소가 소유하며 WAL과 5000ms busy timeout을 사용한다. 글 저장은 댓글과 게시판 이동 이력을 포함한 트랜잭션이다.

## 조립

store, driver, http, clock, settings, fetchLog, ingestor는 소비 앱이 구성한다. fetchLog는 Fetcher에 연결한 것과 같은 인스턴스를 전달한다. 실행 통계·체크포인트·훑기 상태 값은 store 패키지가 소유한다. PoliteFetcher는 사이트마다 한 인스턴스를 재사용한다. Sleeper는 대기 중 인터럽트를 보존해야 한다.

    RunStats stats = new CrawlRunner(store, driver, http, clock, settings, fetchLog).run();
    ArchiveProjection projection = new ArchiveProjection(store);
    Projection p = projection.project(site, selectedBoardIds, false);
    var report = ingestor.ingest(space, site, p.documents(), p.liveDocumentIds());
    for (SourceDocument document : p.documents()) {
      if (report.failures().stream().noneMatch(f -> f.uri().equals(document.uri()))) {
        projection.markProjected(document.documentId(), p.hashes().get(document.documentId()));
      }
    }

실패한 문서를 반영 완료로 표시하면 안 된다. full=true는 전체 재전송과 명시적인 대량 축소를 허용한다. 기본 축소 상한은 20%이며 거부된 투영은 기존 반영 해시와 현존 수를 유지한다.

## 드라이버 계약

- BoardDriver는 게시판과 최신순 목록을 읽고 글 상태를 판정한다. 분류·요약하지 않는다.
- postId는 사이트 안에서 유일해야 한다. 이동 가능한 글은 사이트 전역 id를 쓴다.
- raw를 넘기기 전에 회원 식별 키·내부 id·연락처를 제거한다. 사이트별 제거 필드는 드라이버와 고정 테스트가 소유한다.
- 200 오류 본문을 포함한 삭제·접근 거부 판정은 드라이버 책임이다. 불명확한 오류는 Unknown이며 삭제로 추정하지 않는다.
- 댓글 목록이 불완전하면 commentsComplete=false다. 완전한 목록에서 빠진 기존 댓글만 삭제 상태로 바뀐다.
- 불안정한 raw·조회수·광고 변화는 정규화 내용의 revision을 늘리지 않는다.

ProfileDriver는 html(CSS 선택자)과 json(JSON Pointer)을 지원한다. BoardProfile은 id, name, category, listUrl, postUrl, datePatterns를 가진다. postUrl의 {postId}는 목록에 없는 글의 삭제 확인에도 사용한다. 다음 페이지 선택자는 링크를 반환하며 커서는 다음 목록 URL이다. 게시판 접두어를 쓰면 글 URL에는 로컬 id를 사용한다.

선택적인 author 선택자는 표시명을 읽는다. identitySelectors(CSS 또는 JSON Pointer)와 identityFields는 추가 신원 제거 규칙을 지정한다. raw와 본문은 같은 정화된 페이지에서 읽는다. 프로필의 기본 신원 제거 규칙은 memberId, userId, accountId, internalId, email, phone, contact와 대응 HTML 속성·입력 필드를 제거하고 script를 저장하지 않는다. 소비 앱은 사이트별 신원 필드를 고정 자료로 검증하고 추가 규칙을 지정해야 한다. 설정으로 안전하게 제거할 수 없으면 전용 드라이버가 필요하다. 프로필 드라이버는 댓글 없는 사이트용이며 빈 댓글과 commentsComplete=true를 반환한다.

## 요청과 실행

기본 요청 간격은 사이트 단위 최소 3초, 동시 요청은 1개다. 간격은 늘릴 수만 있다. 429·5xx·연결 실패는 최대 4회 재시도하며 1·2·4·8초 지수 대기와 Retry-After 초 값 중 큰 값을 적용한다. robots 요청·재시도도 같은 간격·통계를 사용한다. 자동 redirect를 따르는 HTTP 클라이언트는 사용할 수 없다.

Retry-After가 60초를 넘으면 이번 요청을 전송 실패로 종료한다. robots는 호스트별 24시간 캐시한다. 404는 허용, 서버·연결 오류는 금지다. 금지 경로 예외는 Permission의 허락 주체·날짜·범위·근거 위치가 모두 있을 때만 허용하고 실행 기록에 남긴다.

목록에서 빠진 뒤 삭제·접근 거부로 판정된 글은 목록에 처음 돌아오면 같은 신호여도 한 번 확인한다. 목록에 계속 보이는 종료 상태 글은 변경 신호가 바뀌거나 신호 없는 재확인 주기가 지났을 때만 다시 요청한다. 본문 판정 시각부터 주기를 센다.

재확인 창은 14일, 신호 없는 글 재확인은 7일, 전체 훑기는 10번째 정상 완료 실행마다다. 앞쪽 수집은 작성 시각이 경계보다 엄격히 이전인 글을 만나면 받은 쪽의 나머지 글까지 모두 방문한 뒤 멈추고 다음 쪽은 요청하지 않는다. 같은 쪽에서 시각이 역전되어도 뒤의 새 글을 보관한다. 같은 시각의 글은 postId 순서와 무관하게 페이지를 넘어 모두 읽는다. 재확인 창과 최초 깊이의 멈춤도 쪽 단위이며, 고정글은 깊이·창·커서 판단에서 뺀다. 창 안의 미보관 글과 본문을 한 번도 가져오지 않은 글도 재확인 단계에서 가져오며, 같은 실행에서 이미 시도한 본문은 다시 요청하지 않는다. 경계 쪽에서 멈춰 다음 쪽을 요청하지 않고 이미 보관된 글은 기존 재확인 규칙에 따라 본문 요청을 생략하므로, 쪽 단위 방문 때문에 변경 없는 두 번째 실행의 목록·본문 요청 수가 늘지는 않는다. 다만 같은 시각의 글이 여러 쪽에 걸치면 경계 이전 시각이 나오는 쪽까지 목록을 읽으므로 목록 요청은 여러 번 발생할 수 있다. 같은 쪽의 목록 응답은 실행 내에서 재사용한다.

최초 깊이는 전체 기간이며 시간 예산을 나누어 실행한다. 기존 게시판의 앞쪽·재확인을 모두 진행한 뒤 남은 예산으로 첫 수집과 과거 채우기를 진행한다. 진행 중인 수집 단계와 키를 저장하고 직전 페이지부터 겹쳐 재개한다. 실행 안과 재개 겹침 구간 모두 키·작성 시각으로 글을 건너뛰지 않는다. 저장된 본문 수집 상태와 기존 재확인 규칙, 실행 내 시도 집합으로 재방문의 본문 요청을 억제한다. 앞쪽 키는 방문한 비고정글 키의 최댓값을, 과거 채우기 중 뒤쪽 키는 최솟값과 그 쪽의 겹침 재개 cursor를 보존한다. 최초 깊이도 작성 시각으로 판단하되 경계를 만난 쪽은 끝까지 방문하므로 그 쪽의 깊이 밖 글도 보관할 수 있다. PostKey와 체크포인트 저장 형식은 바뀌지 않아 이전 보관소의 커서를 그대로 읽는다.

재확인·과거 채우기 재개 중에도 앞쪽을 먼저 읽으며, 중단된 작업 위치를 continuation으로 함께 보존한다. 과거 채우기 continuation은 창 안 전체 재확인을 한 차례 마친 뒤 복원하고, 재확인 continuation은 저장 위치에서 이어간다. 재확인 완료 뒤 본문 대기열을 처리하는 단계(PENDING)도 저장해, 목록 비용으로 예산을 소진한 실행이 다음 실행의 재확인을 계속 처음부터 반복하지 않도록 한다. 목록 응답을 받으면 요약과 커서는 끝까지 저장한다. 예산 때문에 미룬 본문 중 창 안의 미수집 글은 해당 게시판의 재확인 단계에서 가져온다. 창 밖이거나 재확인에서 처리하지 못한 본문은 모든 게시판의 앞쪽·재확인 처리 뒤에 영속 큐에서 이어 가져온다. 페이지 이동을 흡수하면서 짧은 예산에서도 이전 목록을 무한히 반복하지 않는다.

전체 훑기는 게시판 스냅샷과 진행 위치를 저장한다. 모든 게시판 목록이 완료되어야 사이트 단위 비교하고 중단·금지·게시판 소실이면 해당 훑기를 폐기한다. 본문을 보관한 누락 글은 드라이버의 `fetchArchivedPost`로 최근 revision URL에서 확인하고, 보관본이 없으면 `fetchPost`로 확인한다. 훑기 확인에서 보관본이 있는 글은 서로 다른 두 훑기에서, 처음 Deleted로부터 24시간 이상 지나 다시 Deleted를 받아야 DELETED가 된다. 그 사이에 본문을 다시 읽거나 목록에서 다시 보면 처음부터 센다(`post.gone_sweep`·`gone_at`). V5 보관소가 시각 없이 남긴 삭제 근거는 근거가 없는 것으로 보고 다음 훑기부터 다시 센다. 이 규칙은 훑기 확인에만 적용한다. 목록에 보이는 글의 본문 재확인은 드라이버의 Deleted를 그대로 따른다. 일시적인 404 한 번이 검색에 있던 글을 지우지 않게 하기 위해서다. 보관본이 없는 글은 투영되지 않으므로 한 번에 DELETED가 된다. 확인 불명·확인 예외 글은 NEEDS_CHECK로 유지하며 투영의 현존 집합에도 남긴다. 글 단위 예외는 실패 수로 세고, 목록 예외는 해당 게시판만 중단한다. 실행 기록은 finally로 마감한다. 게시판 발견 실패는 실행을 마감한 뒤 호출자에게 전달한다. 마감된 실패 실행은 crawl_run.failure_reason에 예외 종류를 남기고 정상 완료 횟수와 훑기 주기에서 제외한다. 훑기 폐기 사유는 sweep.discard_reason에 남는다. 기존 보관소는 열 때 원본을 보존하며 재등장 관측과 실행 실패 열을 자동으로 이행한다.

테스트는 로컬 HTTP 서버와 합성 HTML·JSON만 사용한다.

## 날짜와 검증 범위

상대 날짜는 주입한 Clock 기준 Instant로 변환한다. 목록의 원래 날짜 표기는 해당 글을 가져올 때 raw의 listedDate 메타에 남긴다. 거친 상대 표기를 여러 번 읽으면 작성 시각이 달라질 수 있으므로, 안정된 절대 날짜를 제공하지 않는 사이트는 전용 드라이버에서 정밀도를 처리해야 한다. 일반적으로 목록은 작성 시각의 최신순을 전제하되, 같은 쪽 안의 10:00 → 09:00 → 09:30 같은 시각 역전은 모두 방문한다. 쪽 경계를 넘는 시각 역전은 앞쪽 수집의 보장 범위 밖이다. 경계 이전 글이 나온 쪽에서 멈추므로 다음 쪽의 새 글은 재확인 창 안이고 예산이 충분하면 재확인이 수집하지만, 창 밖이면 다음 전체 훑기에서 발견된 뒤 후속 실행이 본문을 가져올 때까지 늦어질 수 있다. 창 안이라도 예산이 부족하면 수집이 지연될 수 있으며, 전체 훑기도 예산에 따라 여러 실행에 걸칠 수 있다.

검증 명령은 backend에서 `./gradlew :scos-board-archive:check checkModuleGraph`, 저장소 루트에서 `./tools/check-minimal-runtime.sh`다. 테스트는 합성 자료와 localhost 요청만 사용한다.

소비 앱의 드라이버 검증에는 일반 JAR인 [`scos-board-archive-testkit`](../scos-board-archive-testkit/README.md)을 `testImplementation`으로 추가한다. 쪽 넘김 구현은 `PagedBoardDriverContract`, 첫 쪽 전용 구현은 `SinglePageBoardDriverContract`를 상속한다. 글 ID·요청 경로 사상과 고정 자료 준비 훅만 구현하며 프레임워크와 같은 기대값으로 검증한다.
